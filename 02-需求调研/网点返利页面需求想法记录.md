## UI-I-001 每日返利盈亏趋势图

### 1. 原始想法

将每日返利和扣减结果做成类似支付宝“每日盈利/亏损”的趋势图。用户点击某一天后，可以查看该日期更详细的返利计算信息。

### 2. 当前理解

图表以日期为横轴，以当日净返利金额为纵轴：

- 正数：当天形成的返利金额；
- 负数：当天形成的扣减、回扣或冲减金额；
- 零值：当天没有返利或扣减；
- 点击某个日期：选中该日，并在图表上方的详情区展示当天计算摘要；
- 从日期详情可继续查看组成该结果的运单明细和调整记录。

```text
┌─────────────────────────────────────────────────────────┐
│ 9月16日结果                                              │
│ 当日返利  ¥120.00   扣减 ¥30.00   净返利 ¥90.00          │
│ 有效货量  6,200kg   日基准 5,000kg   命中运单 32票        │
├─────────────────────────────────────────────────────────┤
│ 金额                                                     │
│  ↑         ●                                             │
│  │   ●           ●                                       │
│  ├──────────────────────────── 日期                      │
│  │                  ●                                    │
│  ↓                                                       │
│      9/14      9/15      9/16      9/17                  │
└─────────────────────────────────────────────────────────┘
```

### 3. 点击日期后的建议展示内容

| 信息组 | 建议字段 | 当前状态 |
| --- | --- | --- |
| 日期摘要 | 返利日期、统计窗口、结果状态 | 统计窗口已确认；结果状态待 PRD 定义 |
| 货量结果 | 日基准、有效结算重量、差值、命中运单数 | 差值＝结算总重－日基准量，可为正数、负数或0 |
| 金额结果 | 日返利金额、当日扣减金额、补差金额、净返利金额 | 公式与调整规则继续确认中 |
| 政策信息 | 寄件网点、目的流向、产品类型、货物类型、公斤段、基准量、返利单价 | 货物类型数据来源待业务方确认 |
| 异常信息 | 剔除运单数、扫描不达标数、重算次数、待处理异常 | 剔除及扫描细则待确认 |
| 明细入口 | 查看命中运单、查看剔除运单、查看调整记录 | 待页面骨架阶段确认 |

### 4. 交互建议

1. 默认选中最近一个已有计算结果的日期。
2. 点击图表日期点后，只切换上方详情，不跳转页面。
3. 日期点支持悬浮摘要，点击后固定选中状态。
4. 正数和负数必须通过位置、正负号、图标或文字共同区分，不能只依赖颜色。
5. 图表及选中态使用橙色、琥珀色和暖红色，遵循现有暖色 UI 规范，不使用蓝色和绿色。
6. “查看运单明细”和“查看调整记录”属于进一步穿透操作，进入独立明细区或详情页面。

## UI-I-002 按生效范围维护并按月拆分返利配置

### 1. 问题

当前业务主要通过 Excel 导入配置。如果把每条配置拆成每天一行，“网点 × 目的流向 × 产品类型 × 货物类型 × 公斤段 × 日期”会产生大量记录，Excel 导入和系统逐日填写都会很重。

例如仅按以下规模估算：

```text
20个网点 × 10个流向 × 4个产品类型 × 4个公斤段 × 30天
= 168,000条日配置
```

该数量还没有计算货物类型，不适合让用户逐日新增。

### 2. 建议方案

采用“**日期范围维护、系统按自然月拆分、批量导入并存**”的模式：

1. 用户填写生效开始日期和生效结束日期，不再填写维护月份；政策列表、筛选区和编辑区均不展示“维护月份”字段；
2. 范围跨月时，系统按自然月自动拆分为多条月度配置；
3. 周考核在每个自然月内按1—7日、8—14日、15—21日、22—28日、29日—月末重新分段；
4. 用户维护日、工作日、周日、节假日四层基准量与返利单价；
5. 系统根据优先级生成每日有效值，不要求逐日录入；
6. Excel 导入继续保留，用于多网点、多目的流向的大批量维护。

### 3. 建议页面结构

```text
政策适用范围
  寄件网点｜目的流向｜产品类型｜货物类型｜公斤段｜考核周期

生效范围
  生效开始日期｜生效结束日期｜跨月自动拆分

基准量与单价规则
  日｜工作日｜周日｜节假日

每日配置预览
  列表或日历｜日期｜星期｜日期类型｜有效基准量｜有效返利单价
```

### 4. 关键交互

- 生效年月仅作为按生效日期归类的参考结构，不作为政策字段展示或筛选；
- 列表仅展示到考核周期，基准量和返利单价在查看详情时展示；
- 日基准量、工作日基准量、周日基准量、节假日基准量的优先级为：节假日 ＞ 工作日或周日 ＞ 日；
- 日返利单价、工作日返利单价、周日返利单价、节假日返利单价执行相同优先级；
- 节假日字段未填写时，按当天实际星期继承工作日或周日字段，再继承日字段；
- 输入上方规则后，下方列表或日历立即刷新有效值，不再提供“应用全部”按钮，也不展示配置来源；
- 国家法定节假日由系统自动识别并显示，节假日识别优先于星期类型；官方调休上班不改变正常星期分类；
- Excel 导入必须先校验重复、重叠、缺失和覆盖范围，再展示校验汇总和动态说明；不展示差异预览明细表；
- 修改已生效政策时提示将从生效日期开始重算历史返利结果。

### 5. 当前结论状态

以上页面交互已进入原型实现。仍需业务确认：每月配置是否必须在上月月底前完成，以及未维护下月配置时是不参与返利还是沿用上月配置。

## UI-I-003 数十万条配置的异步导入

### 1. 已确认的规模条件

政策导入文件可能包含**几十万条数据**。导入功能必须按大数据量场景设计，不能依赖浏览器一次性加载、渲染和同步校验全部明细。（确认日期：2026-09-18）

### 2. 页面与处理约束

1. 文件上传成功后立即创建导入任务并返回任务编号，关闭页面不得中断处理；
2. 服务端分批解析、校验和写入，页面通过任务状态展示处理进度；
3. 导入记录至少展示总条数、已处理条数、成功条数、失败条数、处理状态和耗时；
4. 错误明细不在页面一次性展开，统一生成错误结果文件供下载；
5. 同一文件重复提交时必须进行幂等校验，避免重复生成政策配置；
6. 大批量导入完成前，不允许将未处理完成的数据作为正式政策参与计算；
7. 导入结果采用全部成功还是允许部分成功，需结合失败处理与回滚成本确认。

### 3. 建议任务状态

```text
待处理 → 解析中 → 校验中 → 导入中 → 导入成功
                         ├→ 部分失败
                         └→ 导入失败
```

### 4. 待确认指标

| 项目 | 当前状态 |
| --- | --- |
| 单文件最大行数 | 待研发评估，至少覆盖几十万条 |
| 最大文件大小 | 待研发评估 |
| 导入完成时限 | 待业务与研发确认 |
| 并发导入任务数 | 待研发评估 |
| 失败策略 | 待确认全部回滚或允许部分成功 |
| 错误文件保留时间 | 待确认 |

## UI-I-004 三个主功能页面

### 1. 已确认的页面范围

当前阶段设置三个一级功能页面：**政策导入、返利管理、返利看板**。（确认日期：2026-09-18）

### 2. 页面职责

| 页面 | 核心职责 | 关键内容 |
| --- | --- | --- |
| 政策导入 | 导入和维护返利政策 | 模板下载、文件上传、异步导入进度、校验结果、错误文件、已导入政策查询与编辑 |
| 返利管理 | T+1日16:00后计算每日返利并由管理员人工审核发放 | 每日计算结果、可返金额、无需返利原因、人工审核发放按钮、处理状态 |
| 返利看板 | 固定查看单个网点的日、周、月、年返利 | 每日返利日历、周期金额卡片、当日各类型返利汇总 |

### 3. 返利管理下钻

返利管理页面必须支持从汇总结果下钻，查看：

- 当日奖励金额及计算过程；
- 日返利差额回扣；
- 周期未达标回扣；
- 改单、删单或政策变化产生的重算调整；
- 命中运单、剔除运单、结算重量和扫描校验结果；
- 返利发起人、发起时间、账户处理状态和操作记录。

奖惩详情采用页签、抽屉或下钻详情页承载，不单独占用一级菜单。

### 4. 页面关系

```mermaid
graph LR
    A[政策导入] -->|提供生效政策| B[返利管理]
    B -->|人工审核并发放| C[奖惩详情]
    B -->|汇总计算结果| D[返利看板]
    D -->|点击指标或日期| C
```

## UI-I-005 返利管理按统计日期范围筛选

### 1. 已确认需求

返利管理页面的“返利统计日期”支持按时间段筛选，不限制为单个日期。日期控件与政策导入页面的“生效日期”控件保持一致。（更新日期：2026-09-20）

### 2. 页面交互

1. 筛选区仅展示一个“返利统计日期”输入框，输入框内以“开始日期 至 结束日期”展示已选范围；
2. 点击输入框后展开一个日历面板，在同一日历内依次选择开始日期和结束日期，支持切换上月、下月；
3. 首次点击确定开始日期，第二次点击确定结束日期；若第二次选择的日期早于开始日期，则以该日期重新确定开始日期；
4. 日期范围包含起止日期当天，选中后突出显示开始日期、结束日期及中间日期；
5. 未同时选择开始日期和结束日期时，不允许确认并提示继续选择；
6. 支持“清除”和“确认日期”。清除日期后不限制统计日期，列表展示全部数据；
7. 点击控件外部区域时关闭日历面板；
8. 点击“查询”后，列表、结果数量及页面汇总数据按所选日期范围刷新；
9. 点击“重置”后恢复页面默认日期范围；
10. 当前 HTML 原型默认展示2026年9月1日至2026年9月18日。

### 3. 后续规格书细化项

- 默认日期范围是否固定为当月1日至当前日期；
- 允许查询的最大时间跨度；
- 日期范围变化后，顶部汇总指标是否按范围累计，以及待发放数量的统计口径。

## UI-I-006 返利管理列表单价与操作

### 1. 已确认需求

返利管理列表增加“返利单价”，操作列提供“查看周期返利”和“发起返利”。（更新日期：2026-09-20）

### 2. 当前页面规则

1. 返利单价展示该条每日返利结果实际采用的有效返利单价，单位为元/kg；
2. “查看周期返利”根据该条政策的考核周期，展示周周期或月周期内每天的重量达标情况和返利金额；
3. 待发放且返利金额大于0的记录显示“发起返利”；
4. 已发放记录显示“已发放”，按钮不可再次操作；
5. 返利金额为0且尚未发生发放时，状态仍归入“待发放”，操作显示“无需返利”，不设置其他状态。

### 3. 后续规格书细化项

- 一条列表结果命中多个返利单价时，列表展示单价范围、最高单价还是拆分多行；
- “查看周期返利”的周、月累计口径及周期明细字段；
- 多条记录批量发起返利的操作规则。

## UI-I-007 返利管理运单详情

### 1. 已确认需求

返利管理列表操作列增加“查看详情”，点击后展示形成该条返利结果的运单信息。（确认日期：2026-09-18）

### 2. 详情字段

| 字段名称 | 说明 |
| --- | --- |
| 运单号 | 返利计算所引用的中心运单号 |
| 发货时间 | 运单发货时间，开单日期与发货日期为同一业务口径 |
| 寄件网点 | 运单起点网点 |
| 目的流向 | 命中的分拨或营运区流向 |
| 产品类型 | 运单产品类型 |
| 货物类型 | 运单命中的轻泡、重泡或重货分类；轻泡对应原轻抛，重泡对应原重抛 |
| 结算重量 | 参与返利计算的重量口径 |

详情顶部同时展示以下计算汇总字段：

| 字段名称 | 说明 |
| --- | --- |
| 总重量 | 当前返利统计日期内参与计算运单的结算重量合计 |
| 基准重量 | 当前结果实际采用的当日有效基准重量 |
| 返利单价 | 当前结果实际采用的当日有效返利单价，单位为元/kg |

### 3. 页面交互

1. “查看详情”与“查看周期返利”为两个独立入口；
2. “查看详情”展示当前返利日期对应的运单明细；
3. 查看详情使用右侧弹层承载，桌面端宽度占页面宽度的2/3，窄屏时调整为全屏宽度；
4. 同一天可能包含大量运单，运单明细使用表格展示并支持分页，页面不得一次性渲染全部数据；
5. 当前 HTML 原型展示12条运单示例，并使用总数和分页器表达大数据量场景；
6. 运单明细只用于追溯计算来源，不在详情内修改运单业务数据。

## UI-I-008 返利统计日期口径

### 1. 页面命名

原“每日返利”页面统一更名为“返利管理”。页面标题、面包屑和三个一级页面的导航名称保持一致。（确认日期：2026-09-18）

### 2. 日期定义

**返利统计日期 T：统计发货时间在 T 日09:00（含）至 T+1 日09:00（不含）的运单；系统在 T+1 日16:00后计算日返利，管理员人工审核后发放。**

示例：返利统计日期为2026-09-18时，对应的发货时间范围为2026-09-18 09:00（含）至2026-09-19 09:00（不含）；2026-09-19 16:00后系统计算日返利，管理员人工审核后发放。

### 3. 展示要求

1. 页面筛选项和结果列表统一使用“返利统计日期”；
2. “返利统计日期”代表统计窗口的起始自然日，不等同于单张运单的发货日期；
3. 运单详情仍展示每张运单实际的“发货时间”；
4. 统计窗口的开始时间包含在内，结束时间不包含在内，避免09:00边界运单重复统计。

## UI-I-009 返利发放后的变化追溯

### 1. 目标

返利发放后，用户需要知道返利金额如何变化，以及哪些运单变化导致了返利重算和账户调整。（确认日期：2026-09-18）

### 2. 列表提示

返利管理列表增加“发放后调整”，直接展示未发放、无调整、已回扣或已补差及累计调整金额。发生调整时使用醒目标识，但金额正负号和文字必须同时表达结果。

### 3. 查看详情

“查看详情”提供三个页签：

| 页签 | 展示内容 |
| --- | --- |
| 当前运单 | 当前参与返利计算的运单及最新业务字段 |
| 返利变化 | 每次运单或政策变化前后的重量、返利单价和返利金额变化 |
| 运单变化 | 全部运单改单、删单、业务类型变化、重量变化及其引起的返利影响 |

详情顶部展示首次发放金额、当前应返金额、累计调整金额和最后变化时间。

### 4. 留痕要求

1. 返利变化仅展示：变更时间、变更前重量、变更后重量、重量差额、变更前返利单价、变更后返利单价、变更前金额、变更后金额、差额；不展示变更来源和账户处理结果；
2. 运单变化至少记录运单号、变更时间、变更类型、变更前归属、变更后归属、变更前后结算重量、重量差额和对应返利调整；
3. 发放后的改单、删单和政策重算不得覆盖原结果，必须追加变化记录；
4. 未发放的记录只实时更新待发放结果，不产生账户调整记录；
5. 重算应返金额增加时自动补发，减少时自动扣款；页面展示每次变化及账户处理结果。
6. “返利变化”中的重量差额支持点击；点击后自动切换到“运单变化”，定位并突出显示产生该重量差额的对应运单变化记录；金额差额只展示，不提供跳转；
7. 用户直接点击“运单变化”页签时，展示当前返利结果下全部运单变化，不默认定位或隐藏其他记录；
8. 运单修改产品类型、货物类型、公斤段或目的流向等归属维度时，系统先按变更前维度从原返利组合中移出该运单并重算原组合，再按变更后维度重新匹配有效政策，将运单计入新返利组合并重算新组合；
9. 业务类型变化前后分别使用各自命中政策的基准量和返利单价。原组合金额变化与新组合金额变化分别留痕，不能只记录两组合并后的净差额；
10. 类型变更后未命中新政策时，原组合仍需扣除该运单产生的返利，新组合不产生返利，并将“未匹配返利政策”记录为异常供查询；
11. 已发放结果发生类型变化时，原组合和新组合分别计算补发或回扣；未发放结果只刷新待发放金额，不产生账户流水。

## BUS-R-001 返利基数及运单准入限制

1. 网点返利以已达标货量为返利基数：始发有效扫描货量为通过全部准入规则的运单结算重量之和；已达标货量=max（始发有效扫描货量－当日货量基数，0）；日返利金额=已达标货量×有效返利单价。
2. 结算重量大于或等于800kg的融速达运单不参与返利。
3. 同分拨寄件运单不参与返利。同分拨按始发分拨与目的分拨相同判断，具体来源字段须人工确认。
4. 未在返利统计窗口内完成始发分拨有效扫描的运单不参与返利；到件、装车、卸车任一扫描均为有效扫描，装车或卸车扫描可以替代到件扫描；同一运单存在多条有效扫描时只计算一次。
5. 因运单修改或删除造成已达标货量变化时，系统自动重算日返利并回滚周度、月度结果；最新应得金额减少的差额自动扣返，已发返利不足时形成待回扣并在后续返利到账后续扣。（更新日期：2026-09-22）
