# PRD 编写边界

**适用范围：网点返利项目后续全部 PRD。**

## 1. 总体原则

PRD 面向产品确认、研发理解和编码智能体生成代码，负责把业务目标、规则、用户可见行为与验收口径说明清楚。具体技术方案由全栈工程师结合现有工程确定，不在产品 PRD 中预先指定。

## 2. 业务 PRD 应包含

- 业务背景、目标、范围和非目标
- 角色、权限和业务对象
- 业务流程、状态流转与规则
- 字段引用及数据口径
- 异常、边界和待确认问题
- 数据规模、时效、准确性等结果型要求
- 可验证的验收标准

## 3. 交互 PRD 应包含

- 页面结构、信息层级和字段顺序
- 控件能力描述、操作流程与联动规则
- 初始、加载、成功、空数据、失败等用户可见状态
- 校验条件、提示文案和交互反馈
- 分页、滚动、响应式和可用性要求
- 可验证的页面验收标准

## 4. PRD 不规定的内容

除非用户明确要求单独编写技术设计，PRD 不指定：

- 技术栈、框架、第三方库及版本
- 接口路径、HTTP 方法、请求响应 JSON、错误码
- 数据库表、字段、索引、SQL 和存储方案
- 组件、类、函数、状态变量和代码目录名称
- 缓存、并发、重试、部署与监控的具体实现

## 5. 面向开发和编码智能体的执行要求

1. 开发前先读取现有工程，沿用既有架构、组件体系、接口规范、权限和异常处理机制。
2. 产品文档可以规定“支持几十万条数据”“只展示当前页”“达到响应目标”等结果，不替工程人员决定实现手段。
3. 工程能力不足或实现口径缺失时，形成技术设计或待确认问题，不把技术假设写成产品事实。
4. 原型中的示例数据只用于说明页面，正式数据来源以项目已确认的系统和接口为准。

## 6. 数据来源人工确认规则

1. 网点返利是独立模块，凡引用外部系统数据，必须在开发联调前由业务负责人和来源系统负责人人工确认字段映射。
2. 每项映射至少记录：本模块字段、来源系统及模块、来源字段名称/编码、业务含义与口径、数据类型/单位/枚举转换、更新时间或取数时点、确认人、确认日期。
3. 未确认项统一标记为“待确认数据来源”；不得根据页面同名字段、原型示例、Excel样例或经验自行认定映射，也不得作为接口联调、计算、校验和验收的最终口径。
4. 一个目标字段由多个来源字段计算时，必须确认计算或转换规则，以及空值、异常值处理方式。
5. 来源系统、字段或口径变化后必须重新人工确认，并评估对历史政策、返利重算及资金调整的影响。
6. 数据来源确认属于数据对接文档内容，除非另有页面需求，不要求在业务页面展示来源系统或来源字段。

## 7. 文档权威顺序

| 内容 | 权威文档 |
|---|---|
| 字段名称、类型、来源、枚举、字段约束 | 字段清单 |
| 当前模块业务规则、状态和动作 | 业务 PRD |
| 页面展示、用户操作和反馈 | 交互 PRD |
| 接口、数据库、代码结构和技术实现 | 技术设计文档 |

发生冲突时，先按以上权威边界定位责任文档，再修订对应来源，不在下游文档重复维护同一事实。
