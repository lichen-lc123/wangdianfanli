# 网点返利端到端业务流程图

> 版本：V0.7  
> 日期：2026-09-23  
> 依据：《网点返利规则梳理问答记录》《网点返利业务逻辑对齐稿》

## 一、总流程

```mermaid
graph LR
    A[配置或导入政策] --> B[校验并生成生效政策]
    B --> C[按返利窗口归集运单]
    C --> D[次日16点后计算每日返利]
    D --> E[管理员人工审核并发放]
    E --> F[返利进入网点账户]
    F --> G[周期数据窗口结束当天17点自动考核]
    G --> H[自动回扣或形成待回扣]
    H --> I[数据变化后持续重算]
    I --> J[按净差额自动发款或扣款]
```

## 二、政策配置与导入流程

### 2.1 手工新增或编辑

```mermaid
graph TD
    A[打开新增或编辑返利配置] --> B[填写日期与基础规则]
    B --> C[多选产品类型货物类型公斤段]
    C --> D[按自然月和排列组合生成待保存原子政策]
    D --> E{全部组合校验通过?}
    E -->|否| F[阻止整次保存并提示冲突组合]
    F --> A
    E -->|是| G[全部原子政策一次保存]
    G --> H[编辑时替换原政策]
```

手工编辑的产品类型、货物类型、公斤段均支持全选、单选和多选且为必填。任一拆分结果存在必填、枚举、内部重复或启用政策效期冲突时，整次不保存，原政策保持不变。

### 2.2 Excel导入

```mermaid
graph TD
    A[上传政策文件] --> B[格式与业务校验]
    B --> C{是否完全重复?}
    C -->|是| D[阻止导入并进入信息池]
    C -->|否| E{是否存在范围交叉?}
    E -->|是| F[提示多政策命中风险]
    E -->|否| G[正常校验通过]
    F --> H[允许继续导入]
    G --> H
    B -->|字段或枚举错误| D
    D --> I[业务人员修改]
    I --> B
    H --> J[按日期与多选维度拆分]
    J --> K[生成生效政策]
```

重复配置判断：寄件网点、目的流向、产品类型、货物类型、公斤段完全相同，且生效日期重叠。考核周期、基准量或单价不同也视为重复。Excel导入允许合格行先导入、失败行进入信息池；手工新增或编辑不允许部分保存。

## 三、有效运单归集流程

```mermaid
graph TD
    A[读取返利日T的运单] --> B{发货时间在T日09点至T加1日09点?}
    B -->|否| X[不计入]
    B -->|是| C{命中政策五个适用范围?}
    C -->|否| X
    C -->|是| D{始发分拨扫描也在同一窗口?}
    D -->|否| X
    D -->|是| E{有到件装车或卸车任一扫描?}
    E -->|否| X
    E -->|是| F{运单已删除取消或作废?}
    F -->|是| X
    F -->|否| G[整票结算重量计入有效货量]
```

目的流向按最终派件分拨判断。营运区政策使用导入时保存的营运区—分拨快照。

## 四、每日返利流程

```mermaid
graph TD
    A[按政策汇总当日有效货量] --> B[按日期类型取得基准量和单价]
    B --> C{有效货量大于基准量?}
    C -->|否| D[返利为0并显示无返利]
    C -->|是| E[超出重量乘有效返利单价]
    E --> F[生成正金额待发结果]
    F --> G{已到窗口结束当天16点?}
    G -->|否| H[继续实时计算]
    G -->|是| I[系统生成待审核日返利]
    I --> J[管理员单条批量或全部审核并发放]
    J --> K[返利发放到网点账户]
```

```text
日返利金额 = max（日有效货量－日有效基准量，0）× 日有效返利单价
```

“全部返利”按当前筛选条件选择所有可发结果，不受分页限制，并展示记录数和总金额。

## 五、周期考核流程

```mermaid
graph TD
    A[周期最后一日窗口结束] --> B[当天17点自动考核]
    B --> C[累计每日有效基准量和有效货量]
    C --> D{周期实际货量达到目标?}
    D -->|是| E[不奖励也不回扣]
    D -->|否| F[短缺重量乘周期最高单价]
    F --> G[按系统计算的全部日返利封顶]
    G --> H{已发返利可扣额度足够?}
    H -->|是| I[自动扣清]
    H -->|否| J[扣除当前可扣额度]
    J --> K[剩余金额形成待回扣]
    K --> L[后续返利入账时自动续扣]
```

```text
周期目标货量 = 周期内生效日的每日有效基准量之和
周期实际货量 = 周期内生效日的每日有效货量之和
周期应回扣 = min（周期短缺重量 × 周期最高返利单价，周期内系统计算的全部日返利）
```

周周期按每月1—7日、8—14日、15—21日、22—28日、29日—月末；月周期按自然月。中途生效或结束只累计生效范围内日期。

## 六、变更重算与净额结算流程

```mermaid
graph TD
    A[改单删单政策修改或其他数据变化] --> B[重算每日返利与周期结果]
    B --> C{原日返利是否已发起?}
    C -->|否| D[更新待发结果]
    C -->|是| E[计算最新周期最终应得金额]
    E --> F[比较已结算净金额]
    F --> G{净差额方向}
    G -->|应多发| H[自动补发]
    G -->|应多扣| I[自动扣款或形成待回扣]
    G -->|无差额| J[只记录重算]
    H --> K[分别记录日调整与周期调整]
    I --> K
    J --> K
```

```text
周期最终应得金额 = 最新日返利总额－最新周期应回扣金额
本次资金差额 = 周期最终应得金额－已经实际结算的净金额
```

资金层只执行一次净差额，明细层分别记录每日返利变化和周期回扣变化。周期短缺减少或重新达标时，系统自动取消待回扣并退回已经多扣的金额。

## 七、返利资金边界

```mermaid
graph LR
    A[网点原充值余额] --> B[不可用于返利回扣]
    C[已发返利] --> D[返利可扣额度]
    D --> E[日差额回扣]
    D --> F[周期回扣]
    G[后续返利入账] --> H[自动续扣待回扣余额]
```

系统独立记录累计已发返利、累计已扣返利、剩余返利可扣额度和待回扣余额。
