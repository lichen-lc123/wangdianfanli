## 数据来源人工确认规则（全局前置条件）

本模块为独立模块。页面中用于校验和匹配的外部系统主数据，须在开发联调前由业务负责人和对应来源系统负责人人工确认“本模块字段—来源系统及模块—来源字段名称/编码—业务口径”的映射，并补充数据类型、单位、枚举转换、更新时间、确认人和确认日期。未确认项标记为“待确认数据来源”，不得依据同名字段、Excel示例或原型数据自行匹配，也不得作为导入校验、联调和验收的最终口径。

该规则不要求在用户页面展示来源字段，也不改变本文定义的页面字段和交互；来源映射变化时须重新确认，并同步评估模板、校验结果和历史导入数据的影响。

## 1. 页面目标

| 项目 | 内容 |
| :--- | :--- |
| 页面名称 | 政策导入 |
| 页面入口 | 网点返利 → 政策导入 |
| 页签 | 政策配置、导入任务 |
| 主要弹层 | Excel导入、导入问题数据 |
| 设计规范 | `RH_design_token_v3.0`；暖橙色、白色卡片、灰色边框 |

## 2. 页面结构

1. 左侧菜单和顶部导航固定。
2. 政策配置页签包含搜索卡片、列表工具栏、内部滚动表格和固定分页；工具栏不提供“复制上月”按钮或复制入口。
3. 导入任务页签包含任务列表、状态、统计数量和问题数据入口。
4. Excel 导入使用三步弹框：上传文件 → 校验与预览 → 确认导入。
5. 问题数据使用右侧抽屉，桌面端约占页面宽度2/3，窄屏使用全屏。

### 2.1 政策配置编辑入口的一致性

政策配置页的“新增配置”和“编辑”打开返利配置抽屉。产品类型、货物类型、公斤段均使用支持全选、单选、多选和标签删除的多选控件，实时展示类型组合数、自然月数及预计生成的原子政策数。具体控件、提交和错误反馈以《政策配置列表交互PRD》为准。

政策模板及问题数据中的日、工作日、周日、节假日返利单价最多保留两位小数。导入时超出精度的行显示对应失败原因并进入信息池，不对单价静默舍入；页面展示的返利单价统一为两位小数。

手工提交与Excel导入共用自然月拆分、三维排列组合、原子政策和重复判定口径，但失败反馈不同：手工提交任一组合失败时整次不保存并保留原政策；Excel导入继续显示汇总，合格行先导入，失败行进入信息池。

## 3. 上传阶段

| 元素 | 规则 |
| :--- | :--- |
| 选择文件 | 接受当前模板支持的 Excel 文件；再次选择同一文件也必须触发校验 |
| 下载导入模板 | 下载最新四档公斤段模板 |
| 上传区 | 仅保留“选择文件”和“下载导入模板”，不提供加载示例文件 |
| 初始状态 | 未选择文件时“确认导入”不可用 |
| 重新选择 | 在预览阶段返回本地文件选择，不保留旧预览结果 |

## 4. 校验汇总

### 4.1 汇总卡片

按顺序展示：Excel总行数、校验通过、进入信息池、生成政策、替换数量。所有数字来自本次校验，不使用固定示例值。

### 4.2 动态说明

- 首次选择文件：说明本次新增、替换、失败和排列组合数量。
- 同名文件存在历史批次：额外提示历史导入次数，并明确本次已按当前启用政策重新校验。
- 再次导入同一内容后，原先新增的政策已成为当前启用政策，预览应相应显示为替换。
- 说明确认导入后的动作：命中旧政策自动停用，新政策启用，文件内重复的后续行进入信息池。

### 4.3 展示边界

校验阶段不展示逐条差异预览表格，不列出单条新增或替换政策。用户通过五项汇总数字和动态说明确认本次处理结果。

## 5. 确认导入

1. 点击“确认导入”后进入导入中状态，防止重复点击。
2. 完成后展示本次新增、替换和失败数量。
3. 存在失败数据时，先完成成功数据导入和旧政策停用，再自动打开本批次问题数据抽屉。
4. 不存在失败数据时关闭导入弹框并返回政策配置列表。
5. 返回政策列表时清空搜索条件并回到第一页，保证本次新政策可见。

## 6. 导入任务列表

| 交互 | 规则 |
| :--- | :--- |
| 查看问题数据 | 仅失败数大于0的批次展示，打开该批次问题数据抽屉 |
| 查看 | 无失败数据时展示任务结果提示 |
| 任务状态 | 区分处理中、导入成功、部分失败和导入失败 |
| 历史记录 | 每次确认导入新增一条批次，不覆盖旧批次 |

## 7. 问题数据抽屉

### 7.1 顶部与工具栏

- 标题为“导入问题数据”，副标题展示导入批次号。
- 展示当前批次问题总数与已选数量。
- 提供“下载选中问题数据”“下载全部问题数据”。未选择时前者不可用。

### 7.2 表格

字段顺序引用《政策管理字段清单》，至少展示：选择、Excel行号、生效日期、寄件网点、目的流向、产品类型、货物类型、公斤段、考核周期、失败原因、处理状态、操作。

表格在抽屉内部支持横向滚动。“操作”固定在最右侧，“处理状态”固定在操作列左侧；其余字段随横向滚动查看。滚动过程中两个固定列始终可见，并使用轻微阴影区分固定区与滚动区。

| 操作 | 交互结果 |
| :--- | :--- |
| 编辑 | 当前行切换为可编辑状态 |
| 保存 | 保存为修正后数据，状态变为待校验；原始数据仍保留 |
| 取消 | 放弃本次未保存修改 |
| 删除 | 二次确认后仅删除信息池待处理记录 |
| 全选 | 选择当前批次全部问题记录，不受可视区域或分页限制 |

### 7.3 下载与二次导入

1. 下载文件包含原Excel行号、完整导入字段和失败原因。
2. “二次导入”关闭问题抽屉并打开文件选择。
3. 修正文件上传后走完整的三步导入流程，生成新批次。

## 8. 页面状态

| 状态 | 用户可见内容 |
| :--- | :--- |
| 初始 | 上传区和模板入口 |
| 解析/校验中 | 进度说明，确认按钮不可用 |
| 待确认 | 汇总、动态说明和确认按钮；不展示差异预览表格 |
| 导入成功 | 结果反馈并返回政策列表 |
| 部分失败 | 结果反馈后自动打开本批次问题数据 |
| 空信息池 | 展示“当前批次没有待处理问题数据” |
| 校验失败 | 保留文件名称并展示失败原因，可重新选择 |

## 9. 可用性与大数据量

1. 页面不得一次性渲染几十万条政策或问题数据。
2. 导入任务创建后，用户关闭弹框或离开页签不应取消已经开始的任务。
3. 表格在内容区内部滚动，表头与关键操作保持可见。
4. 所有危险删除操作使用语义化文案“确认删除”。
5. 状态不能只依赖颜色，必须同时展示文字。
