## 数据来源人工确认规则（全局前置条件）

本模块为独立模块，凡使用网点、目的流向、产品类型、货物类型、公斤段等外部系统主数据，均须由业务负责人和对应来源系统负责人在开发联调前人工确认字段映射。每项映射至少记录：**本模块字段、来源系统及模块、来源字段名称/编码、业务含义与匹配口径、数据类型/单位/枚举转换、更新时间或取数时点、确认人、确认日期**。

未完成确认的字段统一标记为“待确认数据来源”，不得根据页面同名字段、Excel示例或经验自行认定映射关系，也不得作为导入校验、重复判断、接口联调或验收的最终口径。一个目标字段由多个来源字段计算时，须同时确认转换规则和空值、异常值处理方式；来源字段或口径变更后须重新人工确认。本规则只约束数据对接与验收，不要求页面展示数据来源信息。

## 1. 模块目标

政策导入用于业务人员通过 Excel 批量创建、替换和维护网点返利政策。系统需要在几十万行数据场景下完成字段校验、自然月拆分、类型排列组合、重复判定、部分成功导入和失败数据闭环处理。

核心结果是：合格数据形成可参与返利匹配的原子政策；失败数据进入可修改、可下载、可二次导入的信息池；每次导入和替换均可追溯。

## 2. 范围

| 功能 | 说明 |
| :--- | :--- |
| 模板下载 | 下载当前有效的四档公斤段导入模板 |
| 文件上传与校验 | 读取 Excel，校验字段、格式、枚举、主数据、日期及重复配置 |
| 校验汇总 | 展示本次新增、替换、失败及拆分后生成政策数量，不展示逐条差异预览表格 |
| 部分成功导入 | 合格行先导入，失败行进入信息池，不互相阻塞 |
| 政策替换 | 新数据命中当前启用的同维度重叠政策时，确认后仅替换重叠日期，新政策在其完整生效区间启用，旧政策未重叠日期继续有效 |
| 导入任务 | 保存批次、文件、数量、状态、操作人和时间 |
| 问题信息池 | 展示、在线编辑、删除、批量下载问题数据，并支持二次导入 |
| 重复导入 | 同一文件再次导入时重新计算当前差异，不复用历史说明 |

**不在范围：**返利计算、返利发放、周期回扣和返利看板。

政策配置页的手工新增、编辑由《政策配置业务PRD》定义；其自然月拆分、三维排列组合、原子政策和重复判定口径必须与本导入规则一致。处理失败时，手工编辑整次不保存，Excel导入仍按本文件执行合格行先导入、失败行进入信息池。

## 3. 角色与权限结果

| 角色 | 能力与数据范围 |
| :--- | :--- |
| 总部返利管理员（具备政策维护权限） | 查看全部政策；下载模板、上传文件、确认导入、维护和启停政策、查看导入任务并处理问题数据 |
| 网点查看人员 | 不进入政策导入和政策维护页面；仅在返利管理中查看本人所属网点结果 |
| 系统 | 校验、拆分、替换、生成批次、记录历史、打开问题数据页面 |

具体角色绑定沿用现有工程权限体系；政策页面入口、数据读取及维护操作均须限制为具备对应权限的总部人员。

## 4. 业务流程

```mermaid
flowchart TD
    A[下载模板并填写] --> B[选择Excel文件]
    B --> C[创建导入任务并解析]
    C --> D[校验字段与业务规则]
    D --> E[按月及类型组合拆分]
    E --> F{校验结果}
    F -->|通过| G[计算新增与替换]
    F -->|失败| H[准备进入信息池]
    G --> I[展示动态校验汇总]
    H --> I
    I --> J[用户确认导入]
    J --> K[成功政策启用]
    J --> L[仅停用旧政策重叠日期并保留未重叠区间]
    J --> M[失败行进入信息池]
    M --> N{是否存在失败行}
    N -->|是| O[自动打开本批次问题数据]
    N -->|否| P[返回政策列表]
    O --> Q[在线修改或下载修正]
    Q --> R[二次导入并生成新批次]
```

## 5. 核心业务规则

| 规则ID | 规则 |
| :--- | :--- |
| R-001 | Excel 字段名称、类型、来源和枚举以《政策管理字段清单》为准。 |
| R-002 | 生效结束日期不得早于生效开始日期；跨自然月时先按每个自然月拆分生效区间。 |
| R-003 | 产品类型、货物类型、公斤段支持英文逗号分隔多值，按三类取值笛卡尔积拆分；每条正式政策只保存一个产品类型、一个货物类型和一个公斤段。 |
| R-004 | 单行最终生成数量＝覆盖自然月数量×产品类型数量×货物类型数量×公斤段数量。 |
| R-005 | 寄件网点、目的流向、产品类型、货物类型、公斤段相同且生效日期重叠，视为同维度效期冲突；考核周期、基准量或单价不同不能绕过冲突判定。当前文件内部重复按R-006进入信息池；与现有启用政策冲突按R-007作为替换候选处理。 |
| R-006 | 文件内部重复按 Excel 行顺序处理：首次出现且通过其他校验的行可导入，后续重复行进入信息池。 |
| R-007 | 新导入政策与当前启用政策五个业务维度相同且效期重叠时，校验结果列为替换候选，导入确认后新政策按完整效期启用；旧政策只在重叠日期内失效，重叠区间前后仍有效的部分拆分保留；原政策版本和被替换区间留痕。 |
| R-008 | 字段缺失、格式错误、枚举无法识别、主数据无法匹配、当前文件内后续重复行等失败行进入信息池；命中现有启用政策的同维度重叠区间按R-007替换，不作为失败行。 |
| R-009 | 一批数据允许部分成功：成功行先形成政策，失败行不回滚成功行。 |
| R-010 | 同一文件重复导入时，必须基于本次文件内容与当前启用政策重新计算新增、替换和失败数量；历史批次只用于提示和追溯。 |
| R-011 | 每次确认导入生成新批次，不覆盖历史批次、历史问题数据或旧政策版本。 |
| R-012 | 导入完成且存在失败数据时自动打开本批次问题数据；全部成功时返回政策列表。 |
| R-013 | 信息池支持在线编辑和删除；删除只移除待处理记录，不影响正式政策、原导入批次和导入日志。 |
| R-014 | 信息池支持下载勾选记录或当前批次全部问题数据，文件保留待处理记录编号、原 Excel 行号、完整导入字段和失败原因，以便二次导入时关联原记录。 |
| R-015 | 修正文件二次导入时重新执行全部校验并生成新批次；通过行进入正式政策，失败行进入新批次信息池。通过待处理记录编号关联原问题记录，并将其状态更新为“已导入”，保留原失败原因和处理历史；未通过的原记录仍保留，且新批次生成最新问题记录。 |
| R-016 | 同名文件历史次数只用于提示，不作为内容相同的唯一判定依据。 |
| R-017 | 手工新增或编辑中的产品类型、货物类型、公斤段同样支持多选，并复用R-002至R-005的拆分与重复口径；任一生成组合校验失败时整次不保存，不适用R-009的部分成功机制。 |
| R-018 | Excel中的日、工作日、周日、节假日返利单价最多保留两位小数；超出时作为格式校验失败行进入信息池，不静默舍入。导入预览及政策页面统一显示两位小数。 |
| R-019 | 信息池同时支持单条和批量继续导入。批量提交只处理所选“可继续导入”记录，并逐条再次校验；通过的记录独立导入并标记已导入，失败的记录留在信息池、更新为校验失败并显示最新原因，失败行不阻止其他行成功。 |
| R-020 | 本批次全部数据失败、未生成任何正式政策时，批次状态为“导入失败”；至少一条成功且同时存在失败行时，状态为“部分失败”。 |

## 6. 导入任务状态

```mermaid
stateDiagram-v2
    [*] --> 待处理
    待处理 --> 解析中
    解析中 --> 校验中
    校验中 --> 待确认: 形成校验汇总
    待确认 --> 导入中: 确认导入
    导入中 --> 导入成功: 无失败行
    导入中 --> 部分失败: 成功行已导入且存在失败行
    解析中 --> 导入失败: 文件无法解析
    校验中 --> 导入失败: 无可导入数据或任务异常
```

| 状态 | 用户可见结果 |
| :--- | :--- |
| 待处理、解析中、校验中、导入中 | 展示任务进度，不将未完成数据作为正式政策参与计算 |
| 待确认 | 展示新增、替换、失败和生成政策数量，可确认或取消 |
| 导入成功 | 全部合格数据已形成正式政策 |
| 部分失败 | 合格数据已形成政策，失败数据已进入信息池 |
| 导入失败 | 未形成正式政策，展示失败原因和重试入口 |

## 7. 信息池状态

| 当前状态 | 触发动作 | 后置状态 | 结果 |
| :--- | :--- | :--- | :--- |
| 导入失败 | 进入待处理信息池 | 待修改 | 保存原始数据、失败字段和失败原因，等待业务人员处理 |
| 待修改/校验失败 | 在线编辑并保存 | 待校验 | 保留原始数据，保存修正后数据，等待重新校验 |
| 待校验 | 重新校验失败 | 校验失败 | 更新失败字段和失败原因，可继续编辑 |
| 待校验 | 重新校验通过 | 可继续导入 | 本次数据已通过校验，等待业务人员提交导入 |
| 可继续导入 | 单条或批量继续导入时再次校验成功 | 已导入 | 生成正式政策，保留原始数据和处理记录 |
| 可继续导入 | 单条或批量提交时发现数据冲突或不合格 | 校验失败 | 更新失败原因，不生成该条正式政策 |
| 原问题记录 | 修正文件二次导入且对应数据通过校验 | 已导入 | 按待处理记录编号关联；原始失败原因和处理历史保留，不再作为待处理问题展示 |
| 待修改/待校验/校验失败/可继续导入 | 删除并确认 | 从当前信息池移除 | 仅移除待处理记录，原导入批次及日志保留 |
| 待修改/校验失败 | 下载修正后二次导入 | 原记录不变；新批次处理中 | 原记录与原批次保留；新批次重新执行完整校验 |

## 8. 数据规模与结果要求

1. 单个导入文件可能包含几十万条数据；文件上传后应形成可持续处理的导入任务，用户离开页面不得导致已创建任务丢失。
2. 未处理完成的数据不得参与正式政策匹配。
3. 导入任务必须展示总行数、已处理或通过数量、失败数量、替换数量、操作人和时间。
4. 页面不得要求一次性展示几十万条明细；列表和问题信息按可用方式分页或分段加载，具体实现由技术设计确定。
5. 重复确认、页面刷新或网络重试不得导致同一导入任务重复执行；具体幂等方案由技术设计确定。

## 9. 异常与边界

| 场景 | 系统处理 |
| :--- | :--- |
| 文件格式不支持或无法解析 | 阻止进入预览，展示可理解的失败原因 |
| 文件没有业务数据 | 阻止确认导入，提示文件无可导入数据 |
| 全部行失败 | 不生成正式政策，全部问题行进入信息池并自动打开问题页面 |
| 部分行失败 | 成功行正常导入，失败行进入信息池 |
| 文件内重复 | 首行按正常规则处理，后续重复行进入信息池 |
| 命中当前启用政策 | 预览显示替换候选及被替换日期范围；确认后新政策启用，旧政策仅在重叠日期失效，其未重叠日期拆分保留 |
| 同一文件再次选择 | 重新触发解析与校验，可显示历史导入次数 |
| 信息池在线删除 | 不删除原始导入日志和已成功政策 |
| 二次导入再次失败 | 失败数据进入新批次信息池，原批次不覆盖 |

| V-012 | 导入返利单价含3位小数 | 对应行校验失败并进入信息池，单价不自动舍入 |

| V-015 | 重新校验失败或继续导入时发现冲突 | 状态为校验失败，展示最新失败原因，不生成正式政策 |
| V-016 | 批量继续导入含多条可继续导入数据 | 每条记录独立再次校验；通过者导入并标记已导入，失败者留池并显示最新原因，成功记录不回滚 |
| V-017 | 单条继续导入 | 仅该条记录再次校验并独立导入；其他信息池记录不受影响 |
| V-018 | 修正文件二次导入通过 | 按待处理记录编号关联原问题记录并标记为已导入；原失败原因和处理历史保留 |
| V-019 | Excel全部行校验失败，未生成正式政策 | 批次状态为导入失败；失败行进入信息池 |

## 11. 开发联调确认事项

以下均为进入开发或联调时需要核定的技术容量及数据来源，不代表业务规则未确认：

1. 大文件导入完成时限、并发任务数量及任务保留期限，作为开发阶段的容量与技术设计事项确认，不构成产品规则缺口。
2. 货物类型产品枚举已确认为轻泡、重泡、重货；开发联调时须按全局数据来源规则确认来源系统字段和转换方式。不得把历史旧称轻抛、重抛当作当前产品枚举，也不得在来源映射确认前用于正式匹配和验收。
