# 组件与交互规则

## 一、通用控件

**Button**

- 主/次按钮默认高度：`32px`
- 小按钮高度：`28px`
- 默认小圆角
- 同一操作区只允一个主按钮

**Input / Select / DatePicker**

- 主输入控件默认高度：`32px`
- 文字字号优先 `13/14px`
- 必填标识由 label 承担，不在 placeholder 里写“必填”
- placeholder 只写输入预期，不写整句说明

**SelectWithSearch（带搜索下拉单选）**

- 打开下拉后输入关键字即时过滤（不点击按钮）；输入关键字时下拉保持展开
- 编码前缀匹配、名称包含匹配
- 选项超过 30 条时下拉内分页（每页 10 条）；Mock 主数据通常不超过 30 条
- 选中项默认按 `{Code} {Name}` 展示，调用页可覆盖展示格式
- 调用页声明「可清空」时提供清空入口；清空后联动字段恢复初始态
- 无匹配时下拉内展示「无匹配选项」，不自动关闭

**BatchSearchInput（批量文本搜索）**

- 支持换行或英文逗号分隔多值，查询前 trim 首尾空白
- 连续分隔符视为无效输入，提交时提示「请输入有效的查询值」并阻断
- 多值间为「或」关系，任一值命中即返回；单值精确匹配
- 上限按调用页声明（默认 1000 行），超出阻断并提示
- 点击「搜索」按钮或输入框内 Enter 触发，不即时查询

**筛选区搜索按钮（全站统一）**

- 列表/查询页筛选区主按钮文案统一为 **「搜索」**，次按钮为 **「重置」**
- 禁止使用「查询」作为按钮文案（页面名称如「客户应收查询」不受影响）
- 实现：`DocumentListQueryActions` / `QueryPageFilterBody` / `FilterActions` 默认 `searchLabel` / `primaryLabel` 均为「搜索」

**DateRange（日期区间）**

- 开始日期不晚于结束日期；不满足时字段下方红字提示
- 快捷选项（今天/本周/本月等）由调用页声明，点选后立即写入对应起止日期

**TextArea**

- 高度按内容区块决定，不允许默认过高
- 字符数提示放右下或区块底部

**Switch**：只用于即时切换状态，不用于需二次确认的危险操作。

**Checkbox**：尺寸锁定 `16x16px`，微圆角 `2px`，选中与非选中过渡需清晰。

## 二、表格类组件

**列类型**

当前项目允许的常见列：复选列、展开列、链接列、状态列、人员列、人员+操作 icon 列、时间列、金额列、长文本列、操作列。

**表格规范**

- 常规表头/数据行高度：`38-46px`
- 表头字重与排版：统一采用中粗度中性深灰 `font-medium text-text-2`（字号 `14px`，字重 500），禁止全黑加粗 `font-bold`（700），保持精致清爽的紧凑后台质感
- 不同明细层级允许局部更紧密表格
- 复杂列表必须支持横向滚动
- 主列表统一使用原型 `src/components/ListTable.tsx`，由页面配置提供列、单元格、空态和行操作；页面不得重复实现同职能的 `<table>`。
- `DocumentListPage`、`QueryListPage` 和 `SettlementDocumentListPage` 可以保留业务行为差异，但共享 `ListTable` 的表头、列宽、横向滚动、分页前的表体容器和操作列基础结构。
- 详情页、编辑页和弹窗内的紧凑表格属于另一种表格族：底层外壳统一使用 `TableShell` / `TableFrame`；单据明细使用 `DocumentLineTable`，详情页关联单据使用 `DocumentRelationTable`，商品/单据选择器使用 `PickerTableShell`。领域组件只保留业务列、单元格、空态文案和合计逻辑，不反向塞入主列表组件。

**分页交互**

- 分页区与表格区分层，不混入表格内部
- 分页器需完整呈现：前后翻页箭头（带 Disabled 反馈）、主分页数组、容量切换器、跳转输入框

**基础选择控件**

- `Checkbox`、`Radio`、`Switch` 等共享控件必须支持键盘操作、焦点反馈和对应 ARIA 状态；页面不得用普通 `div` 代替可交互控件。
- 选择器、分页容量菜单等弹出选项使用 `button` 或等价的语义元素，并声明 `aria-expanded`、`role="listbox"` / `role="option"` 等状态。

**可编辑子表格**

- 小屏优先横向滚动，不拆成多张独立卡片。
- 明细表外壳统一使用 `src/components/DocumentLineTable.tsx`，关联表使用 `src/components/DocumentRelationTable.tsx`，选择器使用 `src/components/PickerTableShell.tsx`，其他紧凑内层表格直接组合 `src/components/TableShell.tsx` 或 `TableFrame`；页面内不得重复实现 `overflow-x-auto`、边框、`thead`、`colgroup` 和通用表头。

**排序表头**

- 具备正逆序特征的列必须携带排序双向箭头
- 点击表头需触发三态循环和视觉高亮
- 排序触发器使用可聚焦的 `button`，表头同步声明 `aria-sort`，不可用普通 `div` 承担点击。

## 三、筛选与切换

**筛选区**常见组成：搜索框、状态切换 Tabs、快捷筛选项、高级筛选入口。

**Tabs / 切换器**：用于切换视图或状态集合，不与普通按钮视觉混淆，默认后台风格轻切换，不使用品牌化强视觉胶囊。

## 四、信息块组件

**提示信息块**：用于说明填写规则、风险提示、历史说明；背景使用 `bg-brand-1` 浅橙色、边框使用 `border-brand-3`、圆角小；不用作成功反馈。

**详情信息块**：由标题、标签、信息对、长文本组成，允许图文混合，优先信息对齐。

**步骤条**：详情流程页可用；当前步骤、已完成、未完成要显式区分；服务流程理解，不做装饰。

## 五、个人信息下拉

必须包含：

- 头像信息区
- 分组菜单
- 至少一个状态块、进度块或开关项
- 退出或系统级操作

菜单项规则：

- 常规菜单项高度：`40px`
- 分组之间用分隔线
- 支持箭头进入二级能力
- 支持内嵌 switch

## 六、可编辑子表格

适用场景：采购/销售单据的商品明细、出入库明细录入、盘点/调拨子项维护。

规则：

- 表头与静态表格一致
- 编辑行和只读行可混排
- 新增入口放表格底部
- 小屏优先横向滚动，不拆成多张独立卡片

## 七、金额与小数展示

- 金额类字段统一保留 2 位小数、千分位展示（如 `¥1,234.56`），取整算法与价税计算链见全局规则《4.强盛进销存通用全局规则和要求》§2.2、§2.6，各 Demo PRD 不再重复定义
- 单价类字段最多 4 位小数，按录入值原样展示；**网点返利项目的返利单价为业务专属规则，最多输入两位小数并统一显示两位小数**
- 只读金额统一由系统计算，禁止手工录入

## 八、弹窗与选择器（Modal & Pickers）

适用：轻量配置的查看/新增/编辑、二次确认、单据与商品选择器。轻量配置完整约定见 [08-轻量配置与弹窗表单约定.md](./08-轻量配置与弹窗表单约定.md)。

| 约定项 | 规格 |
| :--- | :--- |
| 标题区 | 左标题，右关闭 `×`（`aria-label="关闭"`）；底部 `border-b border-line-1` |
| 内容区 | 字段或表单；过长时中部滚动，标题与底栏固定 |
| 底栏 | 右对齐按钮；顶部 `border-t border-line-1`；查看=`关闭`+`编辑`，编辑=`取消`+`保存` |
| 宽度 | 轻量约 `480–560px`；中量 `720px`；商品选择器 `980px`；单据选择器 `960–1100px` |
| 状态字段 | 内容区「使用状态」；禁止标题栏右侧徽章 |
| 无障碍与焦点 | 内置 Focus Trap 焦点锁定循环；Esc 触发安全退出；弹出时锁定 Body 滚动条 |

**商品多选选择器（ProductPickerModal）**
- 左侧分类树 + 顶栏编码/名称即时搜索
- 底部左侧已选数量徽标 + 已选明细抽屉面板（支持一键清空与逐行移除）
- 右侧数据表格支持分页与禁用已选行，确认时批量带入单据明细

**通用单据与明细选择器（DocumentPickerModal / DocumentLinePickerModal）**
- 单据选择器：单选 Radio 交互，内置单号/供应商/仓库筛选，确认后带入整单关联
- 明细选择器：多选 Checkbox 交互，支持全选/半选、已选计数、未出入库剩余数量高亮

**通用条码编辑器（BarcodeListEditor）**
- 支持 1~20 条商品条形码录入
- 自动 trim 空格，空输入拦截，重复条码即时红字提示与校验阻断

**通用操作下拉菜单（ActionDropdownMenu）**
- 基于 Portal 顶层渲染，脱离父容器 `overflow: hidden` 限制
- 监听 Window Resize 与 Scroll 自动纠偏视口防遮挡
- 危险动作（删除、取消、驳回、完成订单）统一使用 `text-danger` 视觉高亮

## 九、查询穿透组件（QueryKit）

适用：客户应收、供应商应付、库存流水等查询页的摘要、流水明细和穿透交互。实现：`src/components/QueryKit.tsx`。

当前客户应收与供应商应付页面采用「汇总列表 + 独立流水详情页」；当页面明确需要在当前上下文查看明细时，才使用右侧 Drawer。

| 组件 | 用途 |
| :--- | :--- |
| `StatementFlowDetailContent` | 独立详情页或抽屉内的摘要 + 往来流水内容 |
| `StatementFlowDrawer` | 可选右侧抽屉（宽 `720px`），承载 `StatementFlowDetailContent` |
| `QuerySummaryGrid` | 摘要区网格（`bg-fill-2`） |
| `QueryInfoRow` / `QueryMoneyValue` | 查询详情内键值摘要行；金额 `tabular-nums`，负数 `text-danger` |
| `StatementFlowTable` | 往来流水紧凑子表 |

规则：

- 客户应收 / 供应商应付当前使用独立详情路由；若调用页采用抽屉，必须使用右侧 Drawer，宽度 `720px`
- **禁止**用居中 Modal 替代右侧抽屉式往来流水穿透
- 子表正文 `text-text-2`、表头 `font-medium text-text-2`；仅关联单号等链接列用 `text-brand-6` + `font-normal`
- 金额列右对齐、`tabular-nums`；无增减展示 `0.00`（不用 `-`）
- 主列表仍用 `TableCells`（`DataCell` / `MoneyCell`），与子表分工明确

## 十、收付款单据列表（SettlementDocumentKit）

适用：收款单、付款单列表页及红冲确认弹窗。实现：`src/components/SettlementDocumentKit.tsx`。

| 组件 / 配置 | 用途 |
| :--- | :--- |
| `SettlementDocumentListPage` | 配置驱动的收付款列表页（筛选、Tab 计数、排序、分页、行操作） |
| `ListTable` | 所有主列表共用的表头、列宽、横向滚动、空态容器和行渲染基础层；路径：`99-产品原型prototype/src/components/ListTable.tsx` |
| `receiptListConfig` / `disbursementListConfig` | 收款 / 付款列表列定义、筛选区、Tab 与行操作配置 |
| `SettlementReverseModal` | 红冲确认弹窗（详情页与列表页共用） |

规则：

- 列表页状态统一走 `useTableQueryState`；页面文件只保留薄包装（`config={receiptListConfig}`）
- 红冲弹窗禁止在 `ReceiptModulePages` / `DisbursementModulePages` 内各写一套

## 十一、列表查询状态规范（useDocumentListQuery / useQueryListState）

实现：`src/hooks/useDocumentListQuery.ts`（单据列表，含 Tab）、`src/hooks/useQueryListState.ts`（无 Tab 查询页）、`src/hooks/useTableQueryState.ts`（底层）；session 读写共用 `src/hooks/useListSession.ts`。

| 能力 | 说明 |
| :--- | :--- |
| `useDocumentListQuery` | 单据列表统一 Hook；传 `sessionKey` 可恢复筛选/分页/Tab（**全站列表已覆盖**，见下表） |
| `useQueryListState` | 库存流水、即时库存等查询页；兼容旧 session 的 `filters` 字段 |
| `DocumentListQueryActions` / `QueryFilterActions` | 筛选区底部「重置 / 搜索」 |
| `DocumentListFilteredEmpty` / `QueryFilteredEmpty` | 筛选无结果空态 + 「清空筛选」 |
| `QueryPageKit` | `QueryPageFilterSection`、`QueryPageFilterBody`、`QueryPageTableEmpty` |

### 筛选模式（维持双轨）

| 模式 | 页面类型 | 实现 |
| :--- | :--- | :--- |
| **延迟查询** | 主单、收付款、待认款、其他入出库、库存查询 | `updateDraft` + `runDeferredSearch`；点搜索才应用草稿 |
| **即时筛选** | 执行单（出入库/退货出入库）、汇总查询（应收/应付） | `patchFilters` 改 applied 同步生效；搜索按钮仅 `setCurrentPage(1)` |

不强行全站统一为一种模式：主单/复杂条件适合延迟，执行单/汇总看板适合即时。

- 切换 Tab、排序、每页条数时自动回到第 1 页；重置恢复 `initialTab` 与初始筛选项
- **列表 sessionKey 命名表**（`useDocumentListQuery.sessionKey` / 收付款 `listSessionKey`）：

| 页面 | sessionKey |
| --- | --- |
| 采购订单 | `purchase-orders:list-state` |
| 采购入库 | `purchase-receipt:list-state` |
| 销售订单 | `sales-orders:list-state` |
| 销售出库 | `sales-delivery:list-state` |
| 采购退货 / 销售退货 | `purchase-return:list-state` / `sales-return:list-state` |
| 采购退货出库 / 销售退货入库 | `purchase-return-stockout:list-state` / `sales-return-inbound:list-state` |
| 其他入库 / 其他出库 | `other-inbound:list-state` / `other-outbound:list-state` |
| 收款 / 付款 | `payment-receipt:list-state` / `payment-disbursement:list-state` |
| 待认款 / 客户应收 / 供应商应付 | `unclaimed-funds:list-state` / `ar-statement:list-state` / `ap-statement:list-state` |
| 即时库存 / 库存流水 | `instant-stock-query:list-state` / `stock-flow-query:list-state` |

新增列表页须在对应 `*ListConfig` 中同步声明，并在 Demo PRD 验收项中勾选。

## 十二、默认推理规则

当前未单独确认但统一默认：

- 下拉菜单项高度：`32-40px`
- 个人信息面板宽度：`220-260px`
- 顶栏个人信息面板采用白底浅边框轻阴影
