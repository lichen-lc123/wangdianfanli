# 页面模板与实例映射

## 一、页面模板总表

| 模板 | 适用页面 | 当前项目样例 |
| --- | --- | --- |
| 工作台模板 | 首页/导航页 | 工作台首页 |
| 列表页模板 | 查询、管理、台账类页面 | 商品管理列表页、采购订单列表页 |
| 详情页模板 | 单据详情、流程详情、信息总览 | 销售订单详情页 |
| 列表 + 独立详情组合 | 汇总列表穿透到独立明细页的查询场景 | 客户应收查询页、供应商应付查询页 |
| 新增编辑页模板 | 新建、编辑、录入页 | 采购入库单编辑页 |
| 弹层表单模板 | 弹窗查看/编辑、抽屉编辑；轻量配置的资料项维护 | 数据字典资料项弹窗、选商品弹窗、确认弹窗 |

## 二、模板定义

### 工作台模板

必须区块：顶部系统壳、左侧导航、左侧辅助/快捷区、右侧主内容区、最近访问/快捷入口/常用模块区。

设计原则：

- 工作台可以有模块感，但不能变成营销大卡片首页
- 模块区块允许浅卡片，但不允许所有内容都被独立厚卡片包裹
- 首页优先突出“入口效率”，不是“品牌展示”
- 模块容器优先使用 `rounded-lg bg-fill-1 shadow-soft`；如需边界使用 `border-line-1`，避免 `border-line-2` 与整条 `border-t-2` 叠加造成重边
- 快捷入口统一使用品牌橙图标与浅橙 hover；暖金/琥珀/暖红仅用于真实状态、风险或异常，不用于销售/采购/库存等功能分类
- 指标卡默认使用 `bg-fill-2` 中性底色，数值使用品牌橙；只有负数或明确业务状态才使用语义色
- 工作台待办 Tab 复用查询页状态 Tab 的 `TabCount`：计数为纯文本数字，选中项使用品牌橙，未选中项使用 `text-text-3`，不使用独立圆形徽标
- 工作台待办卡片默认使用白底 `bg-fill-1`；预警卡片也使用白底加 2px 左侧语义线，风险色只用于左侧提示线和数字，不铺满卡片

### 列表页模板

必须区块：页面标题区、筛选区、操作区、表格区、分页区。

可选区块：批量操作区、高级筛选入口、标签切换区、汇总统计区。

默认顺序：

```text
页面标题
筛选与切换
操作区
表格
分页
```

约束：

- 禁止把批量操作塞进页面标题行
- 动作按钮贴紧表格；搜索过滤区与动作按钮保留显著留白，不可混排

### 详情页模板

必须区块：breadcrumb 或路径信息、页面主标题、状态步骤或主状态区、主信息区、明细区。

常见补充：日志区、图片/附件区、地址区、备注区、操作记录区。

设计原则：

- 优先做“信息分块”，不是大段描述堆砌
- 重要状态放到首屏靠前位置
- 明细区允许列表、表格、图片信息混合

### 新增编辑页模板

必须区块：页面标题或弹层标题、分组标题、说明区或提示区、表单区、底部操作区。

可选区块：可编辑子表格、历史摘要区、上传区、联系人附加信息区。

布局规则：

- 桌面端优先双列或三列
- 小屏下降列
- 子表格允许横向滚动
- 底部操作区固定为“提交/取消”主次关系

### 弹层表单模板

宽度分档：轻量弹窗约 `480–560px`（常用 `520px`），中量复杂表单 `720px`；选择器类可更宽（如选商品约 `980px`）。

必须区块：标题区（左标题 + 右关闭 `×`）、标题下分割线、内容区（查看字段或表单）、底栏上分割线、底部操作区。

结构示意：

```text
+------------------------------------------+
| 标题                                 [x] |
|------------------------------------------|
| 内容区                                   |
|------------------------------------------|
|                        [次按钮] [主按钮]  |
+------------------------------------------+
```

约束：

- 使用状态等业务字段放在**内容区**，禁止做成标题栏右侧徽章
- 查看弹窗默认不做操作日志；标准主数据操作日志只出现在独立详情页
- 轻量配置 / 字典类优先本模板，不套独立详情页；详规见 [08-轻量配置与弹窗表单约定.md](./08-轻量配置与弹窗表单约定.md)

禁止：在弹窗里塞完整工作台结构；弹层过窄导致双列表单强行挤压；标题区堆启用/禁用/删除按钮。

## 四、新增页面映射规则

新增页面时至少补 3 件事：

1. 属于哪个模板
2. 依赖哪些组件规则
3. 有哪些状态和权限要求

如果仍无法归类，才允许补新规则。
