# 模块契约与原型复刻规范

## 一、目的与范围

本文件沉淀“从字段清单 / PRD / Demo PRD 到前端原型”的复刻规则，用于新增主数据或单据模块时直接复用已跑通的做法。

## 二、信息源优先级

前端实现服从顺序：

1. 字段清单
2. 主 PRD
3. 前端 Demo 版 PRD
4. 当前项目 `AGENTS.md`
5. 当前工程代码结构
6. UI 规范库

冲突时：`字段清单 > 主 PRD > 前端 Demo 版 PRD > 代码现状 > AI 默认习惯`

- 字段清单：字段本体、枚举、必填性、展示位置
- 主 PRD：业务边界、动作规则、异常和引用影响
- Demo PRD：页面结构、控件、显隐、反馈、页面分组

## 三、模块落地原则

**一个模块一套文档组**

```text
模块目录/
├── [模块]字段清单.md
├── [模块]主PRD.md
└── [模块]_前端Demo版PRD.md
```

不要把多个主数据或多个单据强行合并到一个 PRD 里。

**一个模块一个契约文件**

```text
src/contracts/modules/
├── productManagement.ts
├── warehouseManagement.ts
├── purchaseOrders.ts
└── ...
```

- 一个模块一个文件
- `modulePages.ts` 只负责聚合注册
- 复用逻辑统一放在 `shared.ts`

**页面分层**

- `core`：核心业务页，单独实现
- `secondary`：标准管理页，优先由 Generic 骨架承接
- `placeholder`：只保留入口和定位

新增模块前先判断页面属于哪类，不能所有页面都按独立大页硬写。

**路由与页面跳转**

- 页面跳转关系（哪个按钮或链接进入哪个页面）由 Demo PRD 用页面中文名称自然语言描述，如“跳转至采购入库单新增页”“点击进入采购订单详情页”。
- Demo PRD、页面骨架等文档不主动书写 URL 路由地址；页面身份用中文名称标识。
- 实际路由字符串的唯一事实源是原型工程路由表（`src/app/routes.tsx`、`src/app/navigation.ts` 及模块契约 `view` key）；新模块按路由表现有命名规律登记。
- 文档与路由表出现不一致时，以路由表为准，回写文档表述。

## 四、主数据模块复刻规范

适用模块先分流：

| 类型 | 模块样例 | 页面形态 | 详规 |
| :--- | :--- | :--- | :--- |
| 标准主数据 | 商品、客户、供应商、仓库、物流 | 列表 + 独立新增/编辑/详情 | 本节以下条款 |
| 轻量配置 / 字典 | 数据字典 | 工作台 + 弹窗查看/新增/编辑；默认无操作日志 | [08-轻量配置与弹窗表单约定.md](./08-轻量配置与弹窗表单约定.md) |

下列「通用页面结构 / 详情页 / 操作日志」仅适用于**标准主数据**。轻量配置不得照搬独立详情页与操作日志。

适用模块（标准主数据）：商品、客户、供应商、仓库、物流。

**通用页面结构**：列表页、查看页、新增页、编辑页。

**通用动作**

- 支持：查看、编辑、启用、禁用
- 不支持：删除（仓库等业务 PRD 明确允许未引用删除的除外）

标准口径：标准主数据默认不提供删除能力。对象不再使用时统一通过"禁用"处理；已被业务单据引用的数据必须长期保留。仓库等例外以业务 PRD 为准。

**通用字段规则**

- 编码类字段新增可编辑，被下游引用后只读
- 制单信息（创建人/创建时间/最后修改人/最后修改时间）仅在详情页展示，新增页和编辑页均不展示
- 空值统一展示为 `-`
- 新建保存后默认 `使用状态=启用`；新增和编辑表单不提供启用/禁用字段，状态仅通过列表或详情页动作变更

**状态口径**

- 全局统一使用"启用"/"禁用"，不使用"停用"
- 不设 `stopReason`（停用原因）字段；启用/禁用弹窗不要求填写原因
- 弹窗文案通过契约 `statusConfirmText` 配置，未配置时使用兜底文案

**列表页规范**

| 约定项 | 规格 |
| :--- | :--- |
| 筛选区布局 | `grid xl:grid-cols-6` 六列网格，控件 `w-full` 自适应；搜索/重置按钮 `mt-4 flex justify-end` 单独一行右对齐 |
| 可排序列 | 仅 `kind: "money"`（金额）和时间列（`updatedAt`/`createdAt`）显示排序图标；其他列纯文本表头，不可排序 |
| 编码列 | `link: true`，品牌橙文字 hover 下划线，点击跳转详情页 |
| 操作列 | **左对齐**，使用 `TextAction` 文字按钮（brand 色）；禁用操作用 `tone="danger"` 红色文字；不使用 `Button` 组件居中 |
| 分页 | 默认每页 20 条 |
| 导出按钮 | 契约 `showExport: false` 时不渲染；主数据默认不展示导出 |
| 空数据 | 展示 `暂无{singular}档案` 占位行 |

**多条码字段规范**

- 字段类型：`type: "barcodeList"`，存储为 `string[]`
- 列表展示：`kind: "barcodeSummary"`，显示主条码 + 橙色计数 pill（如 `SCAN0001 3个`）；点击 pill 复制全部分号分隔条码到剪贴板并 Toast 提示；hover 显示全部条码分号分隔
- 详情展示：`kind: "barcodeList"`，标签列表展示，不展示 JSON 原文
- 表单编辑：使用 `BarcodeListEditor` 组件（Tag/Chip 标签嵌入式输入框），支持：
  - 主码（第一个 Tag，浅橙背景 + 品牌橙“主”标识）/ 副码（灰色背景）
  - hover 副码显示 ⭐ 按钮可设为主码（移至首位），Toast 提示切换结果
  - ✖ 删除单个条码；空输入按 Backspace 删除末尾条码
  - Enter / 逗号 / 空格触发添加，清空输入保持聚焦（支持扫码枪连扫）
  - 批量粘贴按 `\n , \t 空格` 拆分去重
  - 格式校验（`itemPattern`）+ 防重校验 + 红字提示
  - 一键清空全部条码

**新增/编辑页规范**

| 约定项 | 规格 |
| :--- | :--- |
| 返回列表 | 使用 `BackToListButton`（幽灵按钮 + ArrowLeft 图标），置于页头操作区最左侧 |
| 页头按钮 | `BackToListButton` 最左侧 + `保存` 按钮 |
| 表单分组 | 按 `visibleWhen` 过滤字段，全部分组字段不可见时不渲染空卡片（如制单信息分组在新增/编辑页隐藏） |
| 制单信息 | 新增页和编辑页均不展示（`visibleWhen: () => false`），仅详情页展示 |
| 金额字段 | `type: "money"`，¥ 前缀 Input |
| 必填规则 | 新增/编辑共用同一套 `formSections`，规则完全一致 |

**详情页规范**

| 约定项 | 规格 |
| :--- | :--- |
| 标题 | `{singular} {编码}` 单行（如 `商品 SKU-0001`），不使用大标题 + 副标题 |
| 页头按钮 | `BackToListButton` 最左侧 + 启用/禁用 + 编辑 + 复制新增 |
| headerFields 卡片 | **不渲染**独立的关键信息卡片；所有字段直接进 `detailSections` 分组展示 |
| Tab 切换 | entity 类型**不用 Tab**，平铺所有 `detailSections` 分组卡片 |
| 操作日志 | 最后一个独立可折叠卡片；标题可点击展开/收起，显示"共 N 条"；展开后含日志表格 + 分页（**仅标准主数据**；轻量配置见 08，默认不做） |
| 条码详情 | `kind: "barcodeList"`，标签列表展示 |
| 启用/禁用弹窗 | 读契约 `statusConfirmText` 配置文案，未配置用兜底文案 |

**详情页分组默认顺序**

1. 基础识别信息
2. 经营与控制信息
3. 制单信息（仅详情页展示）

备注字段是否单独成卡片以 Demo PRD 为准，前端不得自行强化布局。

## 五、前端交互复刻规范

**业务单据页面**：列表、新增/编辑、详情页的返回按钮、操作列对齐、价税列命名与对齐、明细合计行列对齐、详情页状态位置等，统一遵循 [07-单据页面复刻约定.md](./07-单据页面复刻约定.md)。主数据页面不适用该文件。

**成功反馈**：全局顶部居中 `Message.success`，自动消失 `2s`，不使用页面内插入式成功提示条。

**错误 / 警告反馈**：`Message.error` / `Message.warning`，自动消失 `3s`。

**TextArea 规则**

- 默认高度按单行展示，输入增多时自动增高
- 不默认渲染成大块文本域
- 适用：备注、地址、禁用原因

**启禁用交互**

- 启用 / 禁用使用列表页操作列 `TextAction` 按钮或详情页按钮触发
- 禁用操作使用 `tone="danger"` 红色文字
- 二次确认弹窗文案通过契约 `statusConfirmText` 配置（标题、正文、确认按钮文案）
- 不设 `stopReason` 字段，弹窗不要求填写禁用原因
- 禁用后同步刷新列表状态
- 成功后显示顶部 toast

## 六、数据与缓存复刻规范

**新增页初始化**

新增页默认使用空白草稿，只保留必要默认值：

- 主数据默认：`状态 = 启用`
- 单据默认：`状态 = 草稿`

禁止克隆第一条 Mock 数据或预填现成业务数据作为新增默认值。

**本地缓存**

当前原型在无后端前提下，统一使用 `localStorage` 做正式保存缓存。列表页、详情页、编辑页优先读取缓存数据，内置 Mock 作为初始种子数据。

适用范围：主数据新增/编辑、单据新增/编辑、启用/禁用状态更新。

**草稿缓存**

草稿缓存是增强能力，非强制要求。建议优先级：

1. 先做正式保存缓存
2. 再做草稿自动缓存
3. 最后补离开页面未保存提醒

## 七、快速复刻步骤

新增模块时建议顺序：

1. 确认字段清单、主 PRD、Demo PRD 齐全
2. 在 `src/contracts/modules/` 新建模块契约文件
3. 在 `src/data/modulePages.ts` 注册聚合
4. 判断走 Generic 页面还是独立页面
5. 核对成功反馈、错误反馈、TextArea、启禁用、缓存逻辑
6. 执行 `npm run build`
