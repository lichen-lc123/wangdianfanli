# AI协作输入输出模板

## 一、文档目的

约束 AI 处理本项目时的输入和输出格式，减少没有边界的自由发挥。

## 二、通用输入字段

无论哪类任务，输入至少应包含：

- 页面名称
- 页面模板类型（dashboard / list / detail / create_edit / modal_form）
- **维护形态**（标准主数据独立页 / 轻量配置工作台+弹窗）；字典类必须选后者并引用 08
- 业务目标
- 关键区块
- 核心操作
- 角色/权限
- 状态集合
- 是否已有 Figma 参考
- 必须遵循的规范章节

## 三、标准输出结构

AI 输出应按下面结构组织：

1. **页面定位**：这个页面在业务主链路中的位置
2. **页面骨架**：区块组成与顺序
3. **关键区块说明**：每个区块的字段、操作、显隐规则
4. **状态与权限**：需要补齐的加载、空态、异常、权限态
5. **引用规范章节**：明确列出遵循了哪些规范文件

## 四、四种任务模式的差异

| 任务模式 | 输入重点 | 输出重点 | 特别禁止 |
| --- | --- | --- | --- |
| 先出页面方案 | 页面目标、用户角色、业务主线位置 | 页面定位 + 骨架 + 状态缺口 | 直接输出代码 |
| 先出结构原型 | 页面区块、关键字段、关键操作 | 结构树 + 层级关系 + 响应式变化点 | 直接输出代码 |
| 直接出前端骨架 | Figma 节点、响应式要求、技术栈 | 组件拆分 + React 结构 + 样式策略 | 擅自改视觉体系、省略异常态 |
| 补齐异常态和权限态 | 已有结构、角色集合、缺失状态 | 缺失状态列表 + 呈现方式 + 落点 | 自行新增规范外组件样式 |

## 五、引用规范的方式

AI 任务中应显式写出：

```text
必须遵循：
- 01-系统级约束与Token基线
- 02-页面模板与实例映射（含当前页面对应条目）
- 03-组件与交互规则
- 04-状态权限与异常规则
- （单据类追加）07-单据页面复刻约定
- （轻量配置/字典追加）08-轻量配置与弹窗表单约定
```

## 六、默认输出纪律

如果信息不全，AI 应：

1. 先按页面模板输出结构
2. 显式标注默认推理规则
3. 不擅自发明视觉风格
